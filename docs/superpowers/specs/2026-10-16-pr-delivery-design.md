## Ownership and lifecycle

Cordis `mythosSdlc` owns policy, private Gitea API requests, PR reconciliation and source completion. It uses the existing `mythosWorkflow.controller.serial()` queue so publication, supplemental messages and workflow decisions cannot interleave. Its timer and registrations follow Cordis lifecycle. SQLite workflow facts remain in M2. Fixed Git export/push runs in the external M2 backend, with host credentials never entering task containers or browser responses. Existing task/runtime APIs remain compatible.

`workflow.delivery` is the durable integration outbox: intent is committed before each external write, each step has a stable identity, and restart first reconciles authoritative external state. Work phases add `PUBLISHING`, `PR_OPEN`, `CLOSING`, `COMPLETED`. Pausing prevents subsequent dispatch; accepted external writes may already have happened and must be reconciled. Native/console coding input is rejected while publishing, PR open, closing or completed. A closed unmerged PR returns to `AWAITING_REVIEW`; an explicit supplemental instruction can then create a fresh candidate/verification and a new immutable delivery. No force pushes.

## Publication contract

Same-origin authenticated console: `POST /mythos/api/work-items/{id}/publish-pr` body `{expectedVersion}`, JSON + X-Mythos-Action + Idempotency-Key; returns 202 current Work Item. This is the operator decision to publish. Repeated requests for the same current candidate return its existing delivery. It requires approved task, phase AWAITING_REVIEW, clean workspace, only expected source file changed, inactive completed CODE request with no pending/new input, and SUCCEEDED fresh VERIFY whose real JUnit and source SHA exactly match the candidate. Hold the CODE admission fence through the decision. Persist policy and delivery intent before external calls.

Delivery ID is SHA256 UTF-8 `workItemId + ':' + candidateCommit + ':' + verificationOperationId`. Head branch is `mythos/<findingId.lower()>-<workId hex first 8>-<candidate SHA first 12>`, target main. Repository is the immutable source allowlisted URL. Outbox steps: PUSH_PENDING -> CREATE_PR_PENDING -> PR_OPEN -> SYNC_SOURCE_PENDING -> COMPLETED; errors retain the pending step, attempts, lastError, nextAttemptAt with capped exponential retry. A reconciliation/identity conflict blocks rather than overwriting or duplicating an external resource.

M2: `POST /api/brain/work-items/{id}/publish-branch`, body `{expectedVersion,deliveryId}`, owner bearer + Idempotency-Key. Publisher independently validates durable PUBLISHING intent, derived ID/branch, exact verified candidate, source/owner/sandbox binding and no active operations. It exports a Git bundle from registered A at clean exact HEAD, imports into a private host bare staging repo without checkout/hooks, and pushes only the fixed candidate SHA to the unique new branch. Host helper is `/home/hx/gitea/git-credential-mythos.py`; sanitize Git configuration and keep credential material outside arguments, URLs, logs and containers. `ls-remote` first reconciles: equal SHA returns success; different SHA conflicts; missing branch may be pushed without force. Return `{deliveryId,repositoryUrl,branch,candidateCommit,candidateTree,remoteCommit,reconciled}`. Never execute caller shell on host or read reference-fix branches.

Gitea client is loopback-only, bounded/timeout-limited, no redirects, private regular credential file (existing mythos-agent username/password). On lost create acknowledgement, list ALL PR states with bounded complete pagination and match exact repository/head branch/candidate plus marker `<!-- mythos-delivery:<id> -->`; ambiguous or incomplete results never authorize another create. Create uses stable title/body and source/candidate/verification references. Gitea installed OpenAPI does not advertise a draft field; create a normal PR requiring external human review/merge. Browser receives only safe PR metadata/links, never credentials or raw API errors.

## Source completion and concurrency

Mock's legacy PATCH has no source CAS and checks old verification state before applying same-body PASSED, so it cannot safely implement atomic closure. Add a narrow, versioned completion integration to the existing Mock (source overlay tracked under `integrations/mock-source/`). JPA `@Version` on the existing revision field plus transactional legacy PATCH prevents lost writes. `POST /api/findings/{id}/ai-completion` body `{expectedRevision,workItemId,ownerId,repositoryUrl,baseCommit,sourcePath,codeFixCommit,prUrl}` atomically validates current binding/status/source identity, then sets verificationResult PASSED, codeFixCommit/prUrl and Resolved/Closed. Exact already-applied target is idempotent even with an old expectedRevision; different or stale decisions return 409. The endpoint is a synthetic local Mock integration, not enterprise authentication or an independent attestation of Gitea facts. SDLC alone establishes the external gates before calling it.

Source adapter reads current raw source, refuses changed owner/repo/baseline/path/work binding or non-In-Progress status except exact completed replay, sends current expectedRevision, and confirms the returned fields. Lost acknowledgements are reconciled by read-before-write/exact target match. Do not mark Work Item COMPLETED before confirmed source completion. Durable delivery retains source/PR/merge/verification references and last sync error for audit/retry.
