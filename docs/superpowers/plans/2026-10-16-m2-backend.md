# M2 Backend Implementation Plan

> Execute inline using superpowers:executing-plans. The user selected backend implementation after the progress review. Preserve their authorization and continue through verification.

**Goal:** Persist and expose truthful work, execution, log and evidence state across browser/API/worker restarts.

**Architecture:** A Python/SQLite workflow store, authenticated loopback HTTP API, independent worker, and detached container supervisor. Reuse the existing SandboxBroker and registry without changing M1 tools.

**Tech Stack:** Python standard library, SQLite WAL, Docker, existing Java/Maven sandbox image; DSH stays 0.2.0-rc.2.

**Spec:** docs/superpowers/specs/2026-10-16-m2-backend-design.md

## Global Constraints

- Preserve existing sessions/services and the operator OS trust-domain boundary.
- Never execute an HTTP command on the host. owner is resolved from operator configuration.
- UNKNOWN is terminal; no automatic command replay. Cancellation must be confirmed.
- Successful VERIFY requires actual exit 0 and nonempty passing JUnit evidence, bound to exact commit in fresh B.
- Keep runtime databases, tokens and artifacts outside Git.

## Review Focus

- Lost launch acknowledgement must not execute a command twice (supervisor locking and worker restart tests).
- Concurrent requests must not create two source Work Items or operation IDs for one idempotency key (store concurrency tests).
- Late completion after a cancel request must preserve actual exit outcome (supervisor/worker tests).
- Missing/truncated logs, malformed JUnit or incomplete cleanup must not masquerade as passed verification (evidence and executor tests).
- Snapshot cursor and owner checks must also apply to logs/events/evidence, not only Work Item list (HTTP tests).
