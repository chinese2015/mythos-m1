# Multi-tenant BOLA Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a reproducible Java 17 tenant-invoice BOLA project and run FND-00016 through the existing Argon owner-approval, verification, and PR workflow.

**Architecture:** Keep a vulnerable project template under `samples/security/demo-tenant-invoice-api/`, then provision its exact base commit to local Gitea. Reuse the existing unclaimed FND-00016 through a loopback-only, revision-checked Mock binding endpoint; extend only the explicit legacy repository/finding allowlists and add a dedicated read-only live receipt.

**Tech Stack:** Java 17 `HttpServer`, Maven offline profile, JUnit 5.10.2; Node.js ES modules; Python 3; existing Spring Boot Mock overlay; local Gitea and Argon/M2 runtime.

**Spec:** `docs/superpowers/specs/2026-10-18-bola-demo-design.md`

## Global Constraints

- Use only synthetic tenants, principals, invoices, and bearer tokens; do not use real payment or personal data.
- Repository: `demo/demo-tenant-invoice-api`; runtime profile: `java17-maven-offline-v1`; no online dependency installation.
- Finding: reuse FND-00016, Owner `owner-aster-01`; do not reset Mock H2 or create a duplicate Finding.
- Mock bind precondition: revision `1`, repo ID `REPO-demo-aster-ui-service`, URL `https://git.example.test/demo/demo-aster-ui-service.git`, base SHA `6a11c9d2e8f34b0a9d5e7c61f2b8a0d4e6c3f1a2`, null `sourcePath`, `Not Started`/`Open`, no Work Item or remediation job.
- Demo identities: bearer tokens `demo-tenant-a`, `demo-tenant-b`, and `demo-admin`; invoice IDs `inv-a-1001` and `inv-b-2001`.
- Baseline contract: exactly 2 JUnit tests, exactly 1 expected cross-tenant failure, 0 errors/skips; candidate changes exactly the mapped source file and no tests/build files.
- Binding endpoint accepts only the exact new repository, FND-00016, its expected prior revision/placeholder identity, and the fixed source path; stale or drifted records return 409.
- PR remains open and unmerged; do not run source completion or claim merge/CI/review success.
- Keep existing FND-00003/00009/00015 tasks, PRs, and Task 5 receipt contracts unchanged.

## Review Focus

- A regular tenant can request another tenant's invoice through a manipulated object ID; the baseline must expose it and the candidate must return 404.
- Tenant ID from query, header, or invoice data cannot override the authenticated principal's tenant; route and principal tests pin the trust boundary.
- Admin access stays cross-tenant while same-tenant, anonymous, and missing-invoice results keep their specified status codes.
- FND-00016 is already bound, claimed, changed, or has a stale revision when provisioning retries; binding must be idempotent for the exact target and conflict on drift.
- Candidate, base SHA, test counts, PR head, or browser snapshot disagree; live acceptance must fail closed and keep the PR open.
